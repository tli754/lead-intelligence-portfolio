Add Vaadin-grid support to modules/imports' StoreLeads import pipeline.

Context: `modules/imports`' StoreLeads preview/commit endpoints (`POST /api/imports/storeleads/preview` and `POST /api/imports/storeleads`) currently only parse plain HTML `<table>`/`<tr>`/`<td>` markup (`domain/storeleads_html_parser.py`). StoreLeads also exports a second, different markup shape — a Vaadin virtualized-grid (`<vaadin-custom-grid>`/`<vaadin-grid-column>`/`<vaadin-grid-cell-content>`, no `<table>`/`<tr>` anywhere), which the current parser returns zero rows for. Confirmed against two real user-supplied exports: `.claude/data/storeLeads_prestaShop.html` (43 rows, 13 columns: domain, estimated_sales_yearly, created, emails, phones, url, pv, employees, status, platform, categories, country, city) and `.claude/data/storeLeads_openCart.html` (same markup family).

There is a separate, older parser for this exact Vaadin-grid markup already in the codebase — `backend/app/domains/companies/parsing.py`'s `parse_storeleads_html` — but it only extracts domain/url/estimated_sales_yearly_usd/source_created_at/emails/phones (deliberately not platform/country/city, per ADR 0002's "Correction (2026-07-28)" section in `docs/decisions/0002-storeleads-import-targets-modules-imports.md`, which documents that a real Vaadin-grid export DOES carry platform/country/city — the original claim that it didn't was based on an incomplete fixture). That parser also writes into the legacy `companies` collection via a different module (`domains/companies/`), not into `companies_pipeline`.

The `companies_pipeline` schema (`modules/companies/domain/models.py`) that `modules/imports` writes to only has fields for domain/normalized_domain and identity.{company_name,platform,country,city} — no fields for emails/phones/estimated_sales_yearly/created_at from the source. So a Vaadin-grid parser for this pipeline only needs to extract domain + platform + country + city; the rest has no destination field and should be dropped, not shoehorned in.

Ask, concretely: give `modules/imports` a second parser (alongside the existing `<table>` one in `domain/storeleads_html_parser.py`) that understands Vaadin-grid markup and extracts domain/platform/country/city, wired into the same preview/commit endpoints (auto-detecting which markup shape was pasted, same way `domains/companies/parsing.py`'s `detect_format` already distinguishes plain-domain-list vs. storeleads_html by marker string) so pasting either HTML shape works through the existing UI without a one-off script. Follow this repo's existing module conventions (hexagonal layout, ports/gateways, camelCase API DTOs) exactly as `modules/imports` already does for the `<table>` parser — see `docs/contracts/completed/imports-storeleads-html.md` and `docs/contracts/completed/storeleads-import-ui.md` for the direct precedent on contract shape, testing, and doc placement.

A prototype proving the row-segmentation technique (tracking `<vaadin-grid-column name="...">` declarations for column order, then grouping `<vaadin-grid-cell-content>` cells by the "Select Row" checkbox boundary) exists as a throwaway script at `/tmp/claude-1000/-srv-lead-intelligence/462aa487-c620-47a0-b3a9-26110440c071/scratchpad/parse_vaadin_grid.py` — reference it for the technique only; design the real implementation properly (own tests, own fixtures under `fixtures/storeleads/`, own error handling for malformed/empty grids) rather than copying it as-is.
